# ADR: Garage S3 clients use the LB; fix the cluster, do not pin

**Status:** accepted (2026-08-30)

Supersedes [2026-08-30-mimir-s3-db-1.md](2026-08-30-mimir-s3-db-1.md) (pinning
Mimir to db-1). That hid split metadata instead of repairing it.

## Context

Caddy on `proxmox-lb:3902` round-robins Garage S3 to db-1 and db-2. When
db-2's sqlite merkle tables lagged or decoded as garbage, the same key was
200 on db-1 and 404 on db-2. Compactor cleanup aborted, Grafana saw
`err-mimir-bucket-index-too-old`. Pinning Mimir (and Attic's S3 endpoint) to
db-1 made dashboards work and left the cluster split.

`garage repair blocks` is not the repair: on this sqlite cluster it panicked
in `RepairWorker` and coredumped db-1.

Nix **substituters** stay on `http://proxmox-db-1:8080/attic`. That is Caddy
truncating multi-chunk NARs on `:8080`, not Garage replication.

## Decision

Attic, Mimir, and Loki talk to Garage at `proxmox-lb:3902`. If a node 404s
objects the other has, repair Garage. Emptying the lagging node's sqlite and
`garage repair -a --yes tables` only works after the source node's merkle
trees are valid (rebuild `merkle_todo`, skip keys shorter than 32 bytes, wait
for `MklTodo` to drain). Do not pin S3 clients to one node.

## Consequences

Write quorum still needs both zones. Emptying db-2's sqlite takes writes down
until tables resync. See
[runbooks/garage-metadata-resync.md](../runbooks/garage-metadata-resync.md).
Caddy `:3902` uses `lb_try_duration 0s` so a slow GET is not retried onto the
other backend mid-object.
